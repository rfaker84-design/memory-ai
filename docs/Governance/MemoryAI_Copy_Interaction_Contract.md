# 忆见 Copy & Interaction Contract

状态：ACTIVE  
适用范围：所有面向用户的 Web、移动端、通知、页面 metadata 与 manifest 文案。  
优先级：在不改变既有产品合同、权限边界、数据模型和服务层的前提下，本规范约束用户可见 Copy 与交互语义。

## 1. 品牌语气

画面负责情绪，文字负责事实和动作。文案应少、准、中性、克制、可理解；不得替用户定义感受、预设人物状态，或用文艺化措辞制造情绪压力。

Splash 固定为：`忆见` / `忆一人，见一生。`

## 2. 禁词与高风险语义

面向用户 UI 禁止死亡、离世、复生、重逢、回来、再次相见/遇见等预设人物状态的表达；禁止“TA 一直在”“正在等你”“正在听/想”等真人在线或现实存在暗示；禁止游戏化的亲密度、等级、签到、连续奖励；禁止创建 TA、我的 TA、TA 管理、Job、Artifact、Provider、Review、Slot 等工程词。

内部变量、数据库 enum、迁移、测试名与历史技术文档不因本规范改名；仅在其进入用户可见界面时替换。

## 3. AI 身份与事实边界

生成内容统一低权重标记为 `AI生成`；人物身份区使用 `AI生成 · 基于你确认的信息`。影像场景需说明：`这段影像由 AI 根据你提供的照片生成，不代表真实发生过的画面。`

不得将生成内容表述为真人复刻、真实复活、本人回应或真人现实观点。未经用户确认的历史事实不得被描述为事实。

## 4. 页面标准文案

- 游客页：`从一张照片开始。` / `一张照片，一个称呼。` / `体验一次遇见` / `开始`。
- 登录：`登录忆见`、`手机号`、`验证码`、`继续`、`登录即表示你已阅读并同意《用户协议》和《隐私政策》`。
- 创建：`从一个称呼开始`、`怎么称呼`、`你们的关系`、`下一步`；照片页使用 `放上一张照片`、`更换照片`、`生日`、`用于年龄与安全确认`、`补充一句（可选）`、`完成`。
- 影像：`正在生成影像`、`通常需要一点时间。`、`影像已生成`、`继续`。
- 聊天：`说点什么…`、`发送`、`AI生成`；不得以角色口吻描述发送中状态。
- 拾忆：`拾忆`、`还没有保存的内容。`、`保存这一刻`、`保存到拾忆`、`确认保存`、`取消`。

## 5. Button vocabulary

优先使用：开始、继续、下一步、完成、确认、保存、查看、返回、删除、取消、重试、发送、登录、购买。避免唤醒、相见、重逢、回来、留住、珍藏、解锁生命等措辞。

## 6. Loading、Error 与 Empty

统一事实型状态：`正在加载`、`正在上传`、`正在生成`、`正在处理`、`正在检查`、`还没有影像`、`还没有拾忆`、`还没有保存的内容`。

网络失败：`网络暂时不可用` / `你的输入已保留，不会自动重发。`  
生成失败：`这次没有生成回复` / `重试`  
Session 失效：`登录已失效` / `重新登录`

## 7. Commerce、权限与高风险操作

Commerce 不得使用悲伤营销、倒计时、假折扣或情绪绑架。影像额度说明必须写明仅在成功并通过质量检查后使用，失败或未通过不扣除。

权限应说明具体用途。照片：`忆见只使用你主动选择的照片。`；相机：`用于拍摄你主动添加的照片。`；通知：`用于提醒影像生成完成。`

删除、注销与支付必须在明确用户操作后确认。删除与注销只陈述资料、数据与不可恢复影响，不使用情绪挽留。

## 8. 交互合同

- Splash 后进入首页；登录状态只改变首页内容和入口，不自动跳转相伴、拾忆或创建。
- 多人物必须由用户明确选择；单人物可自动选择；Owner scoped preference 保持。
- 创建必须由用户明确开始；退出/取消结束 create intent 并清理对应草稿。
- 聊天人物始终可见、消息独立滚动、composer 固定；运行时只播放 approved idle，聊天事件不得切换视频。
- 页面 GET 不得触发昂贵 Provider 生成；普通聊天仅在用户确认后进入拾忆。

## 9. 验收

每次 UI Copy 变更后，对生产用户可见源码进行禁词扫描和对应主链 targeted verification。不得以替换文案为由修改 API、数据库、Provider、媒体 pipeline 或 Commerce 数据合同。
