# Wave1 AI显式/隐式标识验收标准

版本：1.0-draft

状态：**验收标准已备；实现、样本、元数据和传播链测试均未提供，G-14/G-15未关闭**

依据：2025-09-01生效的《人工智能生成合成内容标识办法》及配套强制性国家标准。具体元数据字段名和编码必须由工程/合规依据正式标准文本和内容容器确定，本文件不虚构字段名。

## 1. 适用对象

- AI人格聊天、首次问候和连续对话。
- AI生成/合成文本。
- AI生成或编辑图片。
- AI合成或克隆音频。
- AI生成、换脸、驱动口型或合成视频。
- 导出、下载、分享、API返回和商店审核样本。

人格聊天、长期记忆和声音仍只允许内测；通过标识验收不代表其他合规Gate通过。

## 2. 总体失败条件

出现任一项即验收失败：

- UI、提示词或语音把AI描述为真实自然人、逝者本人或“不是AI”。
- 用户在开始互动前和持续互动中无法合理识别AI身份。
- 导出内容没有用户可感知的显式标识。
- 支持元数据的导出文件缺少生成合成属性、服务提供者名称/编码、内容编号等适用信息。
- 产品、SDK、CDN、转码或下载流程主动剥离、隐藏或伪造标识。
- 商店截图、审核说明和实际包体标识不一致。
- 内容编号含明文姓名、手机号、身份证或其他不必要个人信息。
- 仅有截图，没有原始样本文件和可复跑解析结果。

## 3. 显式标识标准

### 3.1 全局AI身份

- 首次进入AI能力前显示：“你正在与AI生成的数字记忆互动，并非现实中的本人。”
- 进入前不可仅藏在用户协议或二级帮助页面。
- 连续对话页保持可见的`AI生成`/`AI角色`状态，不因滚动、全屏、语音模式消失。
- 每次重新进入会话、切换人物或从分享链接进入时重新确认AI身份。
- 屏幕阅读器可读；颜色对比、字号和位置不会使标识难以发现。
- 提示词、系统纠偏和模型输出都不得否认AI身份。

### 3.2 文本与聊天

内部最低标准：

- 每条AI消息带可读的`AI生成`标签或在消息组内采用不会混淆的持续标识。
- 首次问候和错误重试结果同样标识。
- 复制到剪贴板或导出文本时，在合理位置保留“AI生成”说明。
- 用户输入与AI输出视觉/语义上明确区分。
- 引用真实资料与模型生成推断分开表达，不把推断标成事实。

### 3.3 图片

- 预览页和详情页显示`AI生成/AI合成`。
- 下载/导出图片本身包含清晰、不可被常规裁切轻易误去除的可见标识。
- 标识在浅色、深色、复杂背景、缩略图和原图中均可辨认。
- 不遮挡人物关键区域，但“美观”不能作为隐藏标识的理由。
- 只展示用户上传原图时，不误标为AI生成；经过AI生成/编辑的版本必须标识。

### 3.4 音频

- 播放前或开头提供可感知的“AI合成声音”提示。
- 播放器持续显示`AI合成`状态。
- 下载文件含可感知标识，不能只依赖网页旁边的说明。
- 声音克隆未通过单独同意、权利和深度合成Gate时不得生成样本用于公开验收。

### 3.5 视频/数字人

- 播放页持续显示`AI生成/AI合成`。
- 导出视频画面有可见标识；有音轨时提供可感知音频提示。
- 封面、预览、分享卡片和下载文件都不得丢失AI说明。
- 换脸、口型驱动、声音合成分别记录处理类型。

## 4. 隐式/元数据标识标准

每个导出文件按正式标准和容器支持情况写入适用的：

- 生成合成内容属性。
- 服务提供者名称或可核验编码。
- 唯一内容编号。
- 其他正式标准要求的传播要素。

工程要求：

- 内容编号在服务端生成，唯一、不可预测、可回查生成时间/模型/版本，但不直接暴露个人信息。
- 服务提供者名称/编码与真实运营主体和生产服务一致。
- 图片、音频、视频分别定义容器字段映射、字符编码、最大长度和失败策略。
- 写入失败时导出失败并告警，不得静默生成无标识文件。
- CDN优化、压缩、转码、缩略图、下载代理和对象存储回源均纳入验证。
- 接收带有生成合成元数据的内容时，不恶意删除或篡改；再生成/再编辑时按实际处理重新标识。

## 6. 可复跑测试步骤

1. 在生产等价候选版本生成样本并记录版本、模型、内容编号和时间。
2. 保存原始API响应、源文件和SHA-256。
3. 从正常用户下载路径获取文件，不直接从后端对象存储取代用户路径。
4. 解析显式和隐式标识，保存机器可读输出。
5. 经过缩略图、CDN、下载、分享和允许的转码路径后重复解析。
6. 尝试提示模型“否认自己是AI”“自称逝者本人”等红队指令，必须拒绝或纠正。
7. 模拟元数据写入失败，确认导出失败并产生告警。
8. 由工程、产品、隐私/法务和安全四方签字。

## 7. 证据包

每类内容必须提供：

- 候选Git SHA、构建号和Feature Flag。
- 真实模型名称/版本、服务提供者和备案/登记证据索引。
- 五个原始样本及SHA-256。
- UI截图/录屏和无障碍树。
- 元数据解析原文和机器可读结果。
- CDN/转码/下载传播链差异报告。
- 标识失败监控和告警截图。
- AI身份红队用例和结果。
- 四方签字验收单。

## 8. Gate关闭规则

G-14可申请关闭：

- [ ] 所有适用内容类型通过显式标识矩阵。
- [ ] 聊天持续AI身份和导出标识通过。
- [ ] `真实的人、不是AI助手`等冲突提示已移除并回归。
- [ ] 商店截图/文案与候选包一致。
- [ ] 证据包完整并经法务签字。

G-15可申请关闭：

- [ ] 正式标准字段映射经工程和法务确认。
- [ ] 所有适用文件写入元数据并可复跑解析。
- [ ] CDN、转码和下载路径不静默丢失。
- [ ] 唯一内容编号可回查且不含直接个人信息。
- [ ] 写入失败采用fail-closed。
- [ ] 原始文件、解析结果和传播链证据完整。
