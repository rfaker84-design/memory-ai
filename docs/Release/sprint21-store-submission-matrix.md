## 3. 通用提交包

### A. 主体包

- 营业执照、USCI、法定名称/地址、法定代表人或授权提交人。
- 官网、域名权属、企业邮箱、客服电话、客服和法务值班人。
- APP 备案、ICP备案（平台要求时）、软著/电子版权、商标或名称授权。
- 算法备案、安全评估、模型备案/登记和年度核验材料。
- 税务、银行和结算资料仅上传平台，不进入 Git。

### B. 构建包

- iOS：Archive/IPA 上传记录、Bundle ID、版本/Build、签名、Entitlements、Privacy Manifest、第三方 SDK 列表。
- Android：正式签名包、包名、versionName/versionCode、签名 SHA-256、target SDK/64 位信息、权限和 SDK 清单。
- 统一：SBOM/依赖清单、病毒/漏洞扫描、真机矩阵、弱网与离线行为、后端环境和回滚版本。
- APP 备案名称、包名、签名、主体和商店元数据必须逐字段比对。

### C. 文案与素材包

- 应用名、短副标题/一句话简介、长描述、关键词、分类、内容分级、版本说明。
- 公开能力必须与包体一致；内测能力不得在截图、视频或描述中宣传为公众可用。
- 图标源文件、每平台导出图标、逐平台截图、可选预览视频。
- 截图必须来自拟提交构建，展示真实 AI 标识、隐私选择、账号注销和投诉路径，不得伪造商店状态。
- 支持 URL、隐私政策 URL、用户协议 URL、数据权利 URL 和 AI/模型公示 URL。

### D. 审核包

- 审核账号、验证码绕行的合规测试方案、测试数据和完整功能路径。
- 后端在审核期间保持可用；不使用只对审核员开放的隐藏白名单来掩盖公众版本差异。
- 审核说明至少解释：产品不是逝者本人、AI 功能边界、照片/声音权利流程、显/隐式标识、未成年人阻断、账号/数据删除、投诉申诉、支付和退款。
- 外部硬件、地域限制、内测开关、演示数据和需要附件的资质要写清楚。

## 4. AI 标识提交子包

每个市场都应准备同一份可审计母版，再按平台字段拆分：

1. **产品声明**：商店描述、产品详情页和 App 内均写明用户在与 AI 而非自然人互动。
2. **模型公示**：真实模型名称、备案/登记号、服务提供者；与生产配置一致。
3. **交互显式标识**：聊天消息、首次问候、语音播放、图片/视频生成页面的截图或录屏。
4. **导出显式标识**：导出的图片/视频可见文字或图形标识；音频以可感知方式提示；文本按适用场景标识。
5. **隐式标识**：每种导出文件的样本、元数据解析结果、属性信息、服务提供者名称/编码、内容编号。
6. **传播链验证**：下载、分享、重新上传后标识的保留/识别结果；不得提供移除、伪造或隐藏标识的工具。
7. **投诉下架**：用户和权利人可以从具体内容进入举报；提供工单号、临时下架、申诉和恢复流程。
8. **安全材料**：拟人化互动安全评估、算法备案及平台要求的核验截图/回执。提交回执不得被描述为监管批准。
