## 本地与 CI 验证

使用仓库指定的 Node 20.20.2 / npm 10.8.2：

```sh
npm ci
npm run test:audit-fixes
npm run typecheck
npm run build
npm run verify:tracked-secrets
git diff --check
```

测试覆盖交接账户隔离、一次性草稿、实际 React hook 的登录继续、模态键盘交互、错误分类、异常来源标记、帮助和导航、创建恢复、商业权益、退款边界、实际 API 权限与响应投影。未把这些结果表述为真实 PostgreSQL、真实短信或视频生成的端到端验收。

## Staging 验收

1. 通过现有不可变发布流程生成候选制品、核验 source SHA、current 与 rollback，再部署 Staging。不能把工作区构建或分支名当成运行中的版本证据。
2. 在 Staging 主机上，从相同来源版本运行只读入口：`node scripts/ops/read-staging-release-status.cjs <40位来源SHA>`。输出仅含经筛选的状态，不输出环境变量或凭据。退出码 2 表示 Web 信息可读但整体证据仍不完整；退出码 1 表示采集失败或被阻断。
3. 核验 Worker 版本、实际 schema、能力开关、最近备份上传、告警送达和恢复演练。只读入口不会替这些检查填写 PASS，也不会执行部署、迁移、恢复或重启。
4. 按用户当前确认的测试账户，经正常登录入口复验：游客输入 → 登录 → 选 TA → 草稿恢复 → 手动发送；另验无 TA 创建与拾忆入口。取消登录、切换账户、刷新、请求失败不能意外发送消息或携带他人草稿。
5. 在手机视口与键盘操作下检查 AI 标識可读性、弹层关闭/焦点恢复、生日说明、权益链接及案例展开。

当前交付不包含服务器执行凭据。运行状态、真实登录结果和更新后的页面截图必须在实际部署后补录；这些项目未闭环前，保留待验收状态。
